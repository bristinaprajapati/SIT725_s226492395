# Reflection

For this task, I containerised the Application Module of our group's Student Accommodation System using Docker. I kept things simple by using a single Dockerfile based on Node.js, since my part of the app is just one server without extra moving parts. I used a MongoDB database running on my own computer rather than an online one, to keep things simple. The biggest challenge I faced was getting my Docker container to actually talk to my MongoDB database. At first, it kept failing to connect, and I realised this was because I was using "localhost" in my settings but inside a container, "localhost" refers to the container itself, not my actual computer. Once I understood this, I fixed it by using a special address Docker provides that lets the container reach back out to my computer instead. I also ran into an issue where my app wouldn't start because another version of it was still running and using the same port; I learned how to find and stop that process so I could restart everything cleanly.
Another smaller issue was an early .env configuration mistake, I had created .env.example but forgotten to actually create a working copy named .env, which caused Mongoose to receive an undefined connection string. This taught me to always verify environment variables are being loaded correctly before assuming the code itself is broken. What I found most challenging was understanding why Docker networking behaves differently from running an app directly on my machine, the concept that a container is an isolated environment took some adjustment. What I found most rewarding was seeing the exact same codebase run identically whether I used npm start directly or docker run, and confirming that data submitted through the Dockerised app was correctly saved to and retrieved from MongoDB. This gave me a much clearer understanding of why containerisation is valuable as it removes uncertainty about whether an application will behave the same way on a different machine, which is exactly what I verified by rebuilding and running the container successfully after a fresh clone of my forked repository.
