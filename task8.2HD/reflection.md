# Reflection
For this Task 8.2HD, I containerised our group's Student Accommodation System project using Docker on my Mac. I created a Dockerfile to configure the Node.js application environment and set up a docker-compose.yml file to run both the web server and a MongoDB container simultaneously.   
During the setup process, I ran into two major technical hurdles. First, attempting to run mongo:latest resulted in a crash due to a known Linux kernel incompatibility when running Docker Desktop on macOS. I resolved this by updating docker-compose.yml to use mongo:6. Second, while macOS is case-insensitive with file names, the Linux environment running inside the Docker container is strictly case-sensitive. This triggered MODULE_NOT_FOUND errors when importing model files like authRoutes.js requiring ../models/User instead of ../models/user. I went through the project files and updated all require statements to match the exact lowercase file names in my models/ folder.   
I implemented the required /api/student identity endpoint in server.js. It returns a JSON object containing my full name (Bristina Prajapati) and student ID (s226492395).   
What I found most challenging was troubleshooting environment-specific bugs, such as file-casing mismatches and Docker Compose configuration details. What I found most rewarding was seeing the entire application—including MongoDB persistence, user authentication, and the admin dashboard—spin up cleanly inside isolated containers. Containerisation eliminates "it works on my machine" issues by guaranteeing that the project runs identically across any environment.
